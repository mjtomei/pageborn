Live words and the final draft share the same native-text panel at the bottom of the glasses, over whichever view you were using (paper, figure or conversation). The panel grows from one to three transcript lines as words arrive and shrinks for shorter corrections or review pages. While speaking, a longer draft shows its latest three lines. Cancelling restores the underlying reading or conversation view at the same position without adding a conversation turn. Pageborne pauses reading and shows answers in native text. Swipe to read; single or double tap returns to the same reading position, paused. In Autoscroll and Speed read, double tap opens Ask while a single tap pauses/resumes reading. In Pages, single tap advances and double tap opens the library; use the menu or hold to ask. The glasses menu and phone also offer **Ask** and a typed question field. The microphone button starts recording and changes to a send arrow; tap it again to stop and review. In the Even app this uses the glasses microphone; in a normal browser it requests browser microphone access. The preview's hold gesture and hold-A keyboard shortcut follow the same behavior. Cancellation or focus loss discards a held recording. A tap followed by a hold belongs to the system menu; use a sustained press by itself for voice.

The glasses show the entire locally saved conversation. Questions are right-aligned; answers are left-aligned. Both wrap within 480 pixels, reserving at least 64 pixels at the opposite side of the text area. Phone message bubbles are capped at 92% of the chat width. Speaker labels no longer take up rows, and alignment distinguishes adjacent messages without an extra separator row. Paragraph spacing inside messages is retained. The bottom row keeps the Latest indicator and hold/tap shortcuts without message counters or the Swipe label. Short conversations sit at the bottom of the display; long replies initially show their tail, with preceding messages above when there is room. Swipe up to read earlier text, then down to return to the end and resume following. Returning from reading restores your conversation position and whether you were following. The underlying view remains scrollable while starting the microphone, listening and transcribing. Acceptance swipes choose More, Send or Cancel. After sending, you can continue reading or reopen the scrollable conversation while waiting. Progress appears in the panel or bottom status row. New submissions follow the latest text as it streams. Scrolling up detaches that following behavior; later chunks and completion preserve your message anchor. If you have scrolled back, the top of that older passage remains fixed while the panel covers the lower portion. Voice review/cancel also preserves that place. ## Librarian

Choose **Librarian** in the glasses document picker or phone library to work across the shared desktop library. It is available with an empty phone library and needs no open document. The first question creates a desktop session named Librarian at the root reported by library sync (normally `~/.pageborne/library`, or the desktop's `PAGEBORNE_LIBRARY_DIR`). It does not use a paper session folder or the connection's default directory.

Typed and dictated follow-ups reuse this session across app restarts, separately from per-paper chat. Tap back on the glasses to return to the selection menu. **New Librarian session** in its session details starts fresh while keeping the old desktop conversation. If the desktop library root or identity changes, start a new session before asking. Librarian requires the Pageborne library extension and a Terminal connector that can create sessions; it cannot use a provider-only API or the existing-session-only native Claude connector. Agent permissions stay controlled by the desktop. Library changes reach the phone through the existing Sync library action.

`npm run test:librarian` checks empty-library access, glasses selection, directory selection, paper isolation, dictated review/send, session persistence and reset in Chromium and WebKit with model/desktop fixtures.

## Choosing a model per document

In a desktop connection, the **Model** selector at the top of Ask chooses Claude or Codex for that document. The private installation labels its Claude choice **Claude Fable 5.1**. Librarian has its own selector. Each choice retains a separate desktop session and recent message history; switching back resumes that conversation. It does not copy messages between models or change the model of an already linked desktop session. Desktop settings still control the model within a Codex or manually linked Claude session.

**Settings → Reading and Ask → Default model for new chats** sets the initial choice for documents and Librarian without a saved choice. Existing conversations retain their model; if an older document has both histories, the previous configured agent is initially selected and the other remains available. Selections and defaults persist on this phone across app updates. They are not cross-device preferences. Shared desktop messages continue to sync for the selected model.

Switching keeps submitted desktop work running under its original model, and restores pending replies when you return. Typed drafts are retained separately while the app is running. Finish or cancel a voice recording/review before switching. **New session** remains an explicit reset of the selected model's link; it does not reset the other model.

`npm run test:ask-models` covers legacy chats, separate histories, defaults, drafts, pending submissions, external messages, stale responses, reload and Librarian in Chromium and WebKit. `test:ask-automatic` also checks both choices with the packaged private connection.

## Two connection options

In **Settings → Ask about this**, choose:

| Connection | Phone settings | Conversation |
| --- | --- | --- |
| Custom provider & API key | API format, base URL, model and optional API key | Direct OpenAI-compatible Chat Completions or Anthropic Messages requests. Up to four recent completed question/answer pairs from the saved conversation are sent as follow-up context. |
| Desktop sessions · Even Terminal | Server URL, access token, Claude/Codex, optional working directory | A persistent desktop conversation per paper, server and agent. Switch between Pageborne and the connected terminal using the same session ID. |

These connection preferences are shared across documents. Provider API keys and server tokens are saved on this phone until **Forget connection** is used; they are omitted from diagnostics. API requests go directly to the chosen provider. The endpoint must allow browser CORS. Use **Save connection** after entering the details. A provider does not need a `/models` endpoint if it implements the configured inference API.

Desktop authentication stays in Even Terminal and its Claude/Codex connection. Pageborne does not borrow subscription tokens, create another Codex daemon or change the agent's permission mode. Tool approvals and agent questions are answered in Even Terminal or on the desktop.

## Direct Even Terminal connection

The private debug build can connect automatically using Terminal's saved pairing information. When enabled, connection settings and per-paper directory fields are hidden: open a paper and ask. Existing session links are kept, and session selection remains available. New conversations use Terminal's default working directory. General reading and appearance settings stay available. See [private build configuration](README.md#build-and-verify).

For builds with manual setup, use the pairing URL or QR that Even Terminal already prints. In **Settings → Ask about this → Desktop sessions · Even Terminal**, paste the full URL and choose **Use URL**, choose **Scan QR** to take a photo, or **Choose QR image** to select a screenshot. Pageborne fills in the server address, access token and Claude/Codex choice; then choose **Save connection**. You can still enter the address and token separately. A bare URL clears the previous token, so it cannot accidentally be sent to another server.

QR images are decoded locally with bundled [jsQR](https://github.com/cozmo/jsQR). Pageborne never opens the QR URL, uploads the image, or saves the photo. Only the connection fields are saved on this device; the raw pairing URL is cleared after import. Camera/album access is requested through the Even SDK when the corresponding button is used. In a browser, Scan QR uses the camera file picker when available; on a desktop it opens a file chooser. The current SDK has no API for retrieving the connection saved by the separate Even Terminal glasses app, so import it once into Pageborne.

No Pageborne companion, separate port, proxy, or second token is needed. On stock Terminal, allow cross-origin requests with `--allow-cors` (current releases) or `EVEN_ALLOW_CORS=1`. The local shared-session fork already enables CORS. Allow the Terminal origin in the installed Pageborne package as described below. Importing a QR cannot change the installed package's network permissions.

For `even-terminal --tailscale`, enable its exact `http://100.x.y.z:port` origin (or its tailnet DNS name) in the app build. Both devices must be on the same tailnet. Pageborne retains Terminal bearer authentication and CORS; it does not require a public tunnel. HTTPS Serve endpoints work too. Tailscale encrypts traffic between nodes even for HTTP services ([Tailscale documentation](https://tailscale.com/docs/how-to/set-up-https-certificates)); the web browser still applies its own network restrictions.

Opening the phone Ask tab does not open Ask on the glasses or pause reading. The phone tab omits conversation remote and Back-to-reading controls. Glasses gestures and the completed-reply navigation setting keep their behavior.

For ngrok domains, Pageborne sends `ngrok-skip-browser-warning: 1` on both API and event-stream requests, following [ngrok's API guidance](https://ngrok.com/docs/pricing-limits/free-plan-limits#using-headers). This prevents the free-tier HTML warning from replacing an API response. It does not change TLS verification, redirects, authentication or CORS requirements. Debug diagnostic exports include failed route names, origin and failure category, excluding credentials, session IDs and conversation text.

The default matches Terminal's normal new-session behavior: Pageborne omits `cwd`, and the server uses its configured project directory (or launch directory). Every paper still gets a distinct conversation. **Working directory** optionally supplies an existing absolute path for new sessions. **Ask → Context and session → Session for this paper** can override it for that paper. Leave empty to use the Terminal default. The stock API does not expand `~/` or create directories; a missing directory can silently fall back to the server default, so create it first or select an existing session. Changing preferences never relocates a linked session.

## Shared document library

With the optional `librarySync: 1` Terminal extension, Ask uses the same desktop originals as **Sync library** in the document picker. The default is `~/.pageborne/library`, configured on the server with `PAGEBORNE_LIBRARY_DIR`. Derived reflow/index versions live in its hidden `.pageborne/reflow` subdirectory. A conflicting desktop original requires a sync before asking, so a stale phone copy cannot overwrite it. Existing conversations and their working directories remain intact. On older extensions the per-paper/per-session file behavior below is retained. See [library sync and recovery](integrations/even-terminal/README.md#bidirectional-library-sync).

## Optional session folders in the custom Terminal

**Create separate session folders · custom Terminal** is off by default. It requires the small extension in [integrations/even-terminal](integrations/even-terminal/README.md), installed inside the existing server. That server advertises `pageborne.workspaces: 1` in `/api/info`; only when enabled and supported does Pageborne call `/api/pageborne/workspace` before the ordinary `/api/prompt` request. The standard `cwd` API is unchanged. A server without this feature continues to work with the option off; explicitly enabling it produces a helpful error rather than silently changing directories.

The default base is `~/.pageborne/papers` on the desktop. Set **Folder base** on the phone or `PAGEBORNE_PAPER_BASE` on the custom server to change it. This extension expands `~/` itself. Folders are grouped by durable paper identity, with a fresh child for each new conversation:

```text
~/.pageborne/papers/
  paper-<identity hash>/
    session-<workspace hash>/
      paper.json
      files/
        <content hash>-original.pdf (or .md/.txt)
        <content hash>-reflow.md
        <content hash>-index.json
```

`paper.json` contains the title and paper/workspace identity. On the updated extension, paper files go inside this created session directory, including when its base was customized. Hash-derived names prevent titles from becoming paths and distinguish papers with identical titles. Retried folder requests reuse the same directory, while **New session for this paper** gets a fresh directory. Existing session folders and conversations are never deleted by Pageborne. Claude and Codex sessions have independent directories under the same paper group. Selecting an existing desktop session keeps its original working directory; an explicit existing-directory override bypasses automatic creation. Preparing a folder and then linking a manually started session retains the prepared folder for paper files, without changing that session's working directory.

**Prepare session folder** creates it ahead of time and shows the full path, useful for starting native Claude Remote Control manually before selecting that session. Directory creation runs in the same authenticated Even Terminal process, through filesystem calls; it is not a shell command or a model request. The checked-in extension is copied into the local fork's `dist/routes/pageborne-workspaces.js` and registered by `dist/routes/core.js`. No live server was restarted as part of implementation.

## Existing sessions, session options and the local fork

Open a paper, choose **Ask → Context and session → Session for this paper → Refresh sessions**, select a dedicated conversation, then choose **Use selected session**. Pageborne remembers the link after changing documents and after a phone app reload. A session already linked to another paper cannot be selected accidentally.

The official API accepts agent (`claude` or `codex`), working directory for a new session, and session ID. It does not expose model, reasoning effort or permission controls. Configure those on the desktop and select the session. For Claude, a shared interactive session must be launched/connected through the selected Terminal implementation's sharing mechanism. Independently resuming the same saved UUID in another plain Claude process does not establish shared ownership. In stock Terminal, an unwrapped Claude session can use its SDK backend and the backend's settings instead of an existing live terminal.

The API is present in **0.6.5 (April 25, 2026)**, the earliest release retained in the npm registry. The local fork is based on **0.8.1 (June 5, 2026)**. The latest official artifact inspected was **0.10.5**. The session/message/history/info/event routes needed here exist in both the local fork and the inspected official package. This does not imply a guarantee for all third-party forks. [Official release history](https://registry.npmjs.org/@evenrealities%2Feven-terminal), [official package](https://www.npmjs.com/package/@evenrealities/even-terminal).

The `/path/to/even-terminal` fork works as follows:

- **Codex:** create/resume through the existing shared daemon; Pageborne does not start or stop another daemon.
- **Claude in native Remote Control mode:** attach to an existing session. That connector deliberately cannot create a Claude process. Use **Prepare session folder**, start `claude --remote-control` from that folder on the desktop, then select its session. Existing account/peer-message settings remain unchanged.
- The event stream remains open for the paper being read so the fork keeps its subscription alive. A stopped/disconnected app cannot keep that stream open.
- Native Claude may publish a text snapshot and an idle state without a final result event. Pageborne confirms stable idle text across two observations for that specific connector; explicit failed results are never presented as completed answers.

## Paper files for desktop agents

Starting with 0.8.11, a custom Terminal advertising `pageborne.documents: 1` receives the selected paper's original PDF, Markdown or text file, `reflow.md`, and `index.json` through the existing authenticated connection. The first question introduces their absolute desktop paths. Later questions send a revision, reflow file/line/block pointer, original PDF page or Markdown line, and a short quote of the current position. The agent can read/search elsewhere in the paper with its own tools. It is instructed to read only and verify uncertain OCR or figures against the original; its existing permissions remain in effect. The file list is introduced again if the reflow changes or a new session is selected.

With Pageborne 0.8.12 and an extension advertising `pageborne.documentWorkspaces: 1`, files for a Pageborne-created session go in `<created directory>/files`. Its saved directory is reused even if the default base changes later. Without a created directory, files stay under `~/.pageborne/papers/paper-<identity hash>/files` (or the server's `PAGEBORNE_PAPER_BASE`); this also preserves compatibility with older file-enabled extensions. Upgrading an existing managed session copies its files into the session on the next question and sends the updated paths; old files remain available for earlier references. No working-directory override is required.

Uploads use 768 KiB chunks, owner-only files, SHA-256 checks, resumable offsets, and immutable filenames based on content hashes. Unchanged originals are reused across questions and reflow revisions in the same destination. A new session folder gets its own copy. A manifest maps friendly file names to exact paths; `index.json` maps blocks, figures and footnotes to reflow line ranges and original source locations. The export includes footnotes even though the normal reading flow excludes them.

You can ask during partial reflow: the original PDF is complete and the export identifies how many pages are prepared. The next question syncs changed exports if additional pages have become ready. Old snapshots remain readable, so an earlier question's line references do not move. Leaving Ask keeps an already requested file upload and question submission running; forgetting a paper or connection cancels still-unsent deliveries. Reloading the app during an upload requires sending the question again; once Terminal accepts a question, the existing pending-reply recovery applies. Desktop copies persist when a phone library item is deleted, like the associated desktop conversation.

Stock Terminal 0.10.5's inspected `/api/prompt` contract accepts text/session/provider/cwd, without a file-upload route. Stock sessions receive fresh text context on every question, including after moving to another passage: current focus, reading percentage, PDF page when available, and the surrounding text within the fixed context budget (100,000 estimated tokens). The same paper conversation continues; merely moving through the text sends nothing. PDF context refreshes from the latest prepared text and is labeled partial while reflow continues. The agent is told this snapshot describes the current place, so it does not reuse an earlier focus. No file-writing bootstrap prompt or extension is required for this flow. Direct inference endpoints retain the same fixed text context. An arbitrary inference URL is not itself an agent that can browse a desktop filesystem; provider-specific file/tool support would need a separate integration. The extension uses the same server, port and pairing token; no companion service is needed. See [installation and protocol](integrations/even-terminal/README.md).

## Reading while waiting

The phone Ask pane has a scrollable conversation and a composer anchored at its bottom. Your questions appear right-aligned in bubbles; answers are left-aligned. Visible speaker labels are removed, with accessible labels retained for screen readers. Short conversations sit at the bottom of the history pane; answers stream below earlier messages. Scrolling back through older messages stops automatic following until you choose **Latest message** or submit another question. Enter sends and Shift+Enter inserts a newline; touch keyboards request a Send key. **Context and session** contains the passage preview, connection link and desktop session controls.

Recent questions and answers persist on this device, separately by paper, connection, agent and provider/model. The phone keeps up to 40 turns / 100,000 characters per conversation for the 20 most recently saved documents (including their separate model histories). This display history is separate from the four completed pairs sent to direct providers and from the full conversation retained by Even Terminal. Large source passages and audio are not stored in chat history. Pending Terminal replies reconnect to their original question after leaving Ask or reloading. Existing cached replies appear as assistant messages; supported shared desktop sessions also import recent remote questions and answers. Deleting a paper, forgetting its connection, or starting/linking a different session clears the corresponding local conversation; desktop conversations are retained.

Sending any typed or spoken question returns the glasses to the reading screen while waiting. **Settings → Reading and Ask → After sending a question** defaults to **Open Ask when the agent finishes**; **Keep reading until I switch** disables that automatic opening. This applies to every submission, including follow-ups, and persists across papers. Partial text and tool progress never trigger the switch; it waits for the completed answer. Returning manually to reading while waiting cancels the automatic switch for that question, including at completion. You can open Ask manually while the agent works.

The reading footer distinguishes **Thinking…** (no answer text yet), **Reply in progress** (text has started and the agent is still working), and **Unread reply** (finished with unseen text). Opening the conversation acknowledges it. The footer can also show **Needs a response**, **Check desktop**, or **No new replies**. These indicators appear on glasses and phone. After the voice overlay closes, the reading footer keeps its paused rate alongside the agent notification. Leaving the conversation keeps the active request running, including direct-provider requests; a document change or app shutdown can still interrupt a direct-provider request.

Single tap switches reading/Ask in Pages, or pauses/resumes Autoscroll and Speed read. Page swipes and the phone’s Next page button still advance pages. Double tap opens Ask in Autoscroll and Speed read, and still opens the library in Pages. Single or double tap from Ask returns to reading at the same position, paused. The former single-tap preference is ignored. Menus, mode/document/position pickers, footnotes, transcription review and explicit speed-reading Continue/Restart prompts retain their tap actions. The Ask menu entry and phone Ask button always remain available; keyboard **C** also toggles the conversation. Phone page and play/pause buttons retain their reading actions.

Terminal replies appear incrementally on the phone and glasses while the agent is still working. Pageborne reads accumulated `text_delta` events in approximately 700 ms batches through `/api/messages`; its existing SSE connection keeps the desktop subscription attached. Repeated snapshots replace the draft without duplicating text. You can page back through a partial answer; while browsing earlier text, later chunks or completion preserve that answer page. Returning to the tail resumes following new text. The phone uses a spinner; the glasses use changing dots in native text mode. Both honor the system's reduced-motion setting. Custom-provider and legacy bridge answers still arrive as completed responses.

Return to reading at any point; subsequent incoming text does not replace the document after that manual return. Opening Ask or its footer while a request is pending resumes watching the same question, including after a reload. A completed response shows **Unread reply** until opened; acknowledged replies can be reopened later. A pending prompt is never automatically sent a second time. The reader's location stays separate from the answer's page position.

The active request continues polling about every 700 ms while you read. Other linked desktop replies are checked about every four seconds while Pageborne is running. This includes replies to prompts submitted from the desktop in the linked session. Mobile operating systems can suspend the WebView; Pageborne reconnects and checks when it runs again. These are in-app indicators, not push notifications while the app is stopped.

Session links, a pending request marker, and the latest detected unread desktop reply persist in phone preferences. Reading the reply acknowledges it. Closing Ask during submission still saves the returned session ID. **Check reply** retrieves an already submitted question without submitting it again. An ambiguous network failure never automatically retries a prompt or creates a duplicate session; inspect/select the resulting desktop session before retrying. **Forget connection** clears credentials, in-memory API conversations and local desktop links, without deleting desktop sessions.

## Voice and network permissions

**Settings → Voice input** is shared across documents and independent of the agent connection. **On device · CPU draft + GPU corrections** is the default; old GPU-first preferences migrate to it. Moonshine Tiny (FP32 encoder/Q4 decoder) always drafts on single-thread WebAssembly SIMD. Whisper Small English (FP32 encoder/Q4 decoder) corrects on hardware WebGPU. Missing WebGPU or a failed GPU load is shown in Settings and Ask; CPU dictation remains usable, without silently running the larger model on CPU. Remote speech remains available and does not start local models.

Opening a chat starts both model loads independently. Each has a dedicated worker with no idle expiry. A voice request waits for its own preload, so a slow GPU cannot block the CPU draft. Returning to reading, changing papers, cancelling and editing keep both workers. Cancellation rejects the caller immediately, signals cooperative decoding interruption, and discards late results; it does not destroy the weights. App `pagehide` disposes both workers, with `pageshow` restoring preload if the page returns from cache. An OS process termination or unrecoverable worker/GPU failure can still discard them; **Prepare / retry voice** retries a failed load.

As of 0.8.23, Tiny (~79 MB), both tokenizers/configurations and the runtimes ship in the package. The two larger Whisper Small weights (585,972,125 bytes total) download from a pinned Hugging Face revision after hardware WebGPU is confirmed. Only those exact files can be fetched; streaming SHA-256 and byte-count checks reject corrupted/truncated downloads before inference. Download progress appears in Ask and Settings, and CPU dictation stays available. A 60-second network stall fails with a retry message; preparation allows up to 30 minutes. A completed file is reused if the other fails.

The correction worker caches verified weights in 4 MiB IndexedDB chunks when available. A file becomes readable only after all chunks pass verification; interrupted writes are cleaned up, and stale unfinished downloads are swept after one hour. Warm launches at the same origin can use that cache offline. Quota/private-browsing failures still allow inference but show that caching failed. Browser/OS eviction, clearing app storage, or Even changing the localhost origin can force another download. This is best-effort WebView caching, not the native SDK storage used for documents, and has not been verified across physical-phone launches. Models stay resident until app exit as before. No audio, document text, vocabulary or credentials are sent to the model host. Long audio is split near quiet points into segments of up to 15 seconds.

Version 0.8.21 consumes the glasses' incremental PCM frames, as demonstrated by [Even's official ASR template](https://github.com/even-realities/evenhub-templates/blob/main/asr/src/main.ts). Browser preview uses an AudioWorklet to capture/resample microphone PCM into the same path. After at least 1.25 seconds of new audio, a throttled CPU pass updates the provisional phone text and the glasses' bottom transcription overlay. Only one partial inference runs at a time; incoming frames coalesce instead of creating a queue. Windows are bounded to 15 seconds and advance at low-energy boundaries. This reprocesses growing audio windows using the existing Tiny model, rather than relying on a model-native streaming cache. Provisional words may change, and the final pass on release replaces them before GPU correction. The preceding conversation remains visible and scrollable. Partial text never submits automatically; edit/send becomes available after release. Cancelling, changing papers or leaving Ask invalidates partial results without evicting the models.

**Custom vocabulary** in Settings accepts comma/newline-separated terms (4,000 characters), shared across papers. **Use words from this paper and chat** defaults on. As of 0.8.22, automatic terms are ranked by English commonness and distance from the current reading line, using an offline [wordfreq](https://github.com/rspeer/wordfreq) table by Robyn Speer. Short lowercase technical words qualify; capitalization is no longer required. The score is `clamp(5.5 - Zipf frequency, 0, 3) × 2^(-distance_in_words / 120)`: distance halves the score every 120 words in either direction, and words rarer than Zipf 2.5 (including unknown words) share a capped rarity. Everyday words at Zipf 5.5 or higher receive no automatic boost; scores below 0.2 are also omitted so weak, distant hints drop out on Tiny as well. URLs, overlong fragments and obvious repeated-character OCR noise are excluded. The 4,000-character passage is centered on the source offset, including repeated lines; title terms get weight 0.65 and the last four messages get weights 0.5, 0.35, 0.245 and 0.1715 from newest to oldest. Duplicates retain their strongest occurrence. This is a heuristic, not a learned relevance score or an acoustic confidence estimate.

**Settings → Voice input → View vocabulary hints** shows the normalized hint list for the next recording at your current place. Use **Refresh for current position** after moving; opening the viewer does not load a speech model. Expand **Last transcription** to see a copy of the exact list dispatched with the most recent local transcription, including streaming requests. That snapshot stays unchanged when you navigate, lasts until the app closes, and is excluded from diagnostic exports. Terms are selectable for copying. Remote speech providers receive no local vocabulary hints.

Manual entries take priority, followed by automatic terms in descending score. There is no longer a 24/64-term cap. Tiny uses all eligible terms from the bounded snapshot, with a bounded soft token bias on plausible vocabulary continuations; confidence is measured before that boost. Whisper packs whole terms into its full **223-token** previous-text allowance (half its 448-token context minus one, matching [Whisper's reference decoder](https://github.com/openai/whisper/blob/main/whisper/decoding.py)); it skips terms that do not fit and fills remaining space with shorter lower-ranked terms. The prefix is stripped from output and leaves room for the existing 15-second transcription segments. The installed Transformers.js version exposes `decoder_input_ids`; its higher-level `prompt_ids` path is not implemented, so the prefix is constructed explicitly. Vocabulary guides recognition, does not force spellings, and can still worsen a particular transcription. Terms stay local and are excluded from diagnostics. Remote speech providers retain their completed-recording flow and do not receive this local word list. The data source, generation script and CC BY-SA attribution are in `vendor/wordfreq/`, and included in both build profiles.

**Improve transcription while reviewing** is enabled by default. After the CPU draft opens Send/Cancel, GPU refinement can replace an unchanged draft. Editing, sending, cancelling, starting another recording, changing papers or leaving Ask invalidates late results. Empty/failed correction keeps the original draft. A selected Cancel remains selected when a longer correction adds More. Disabling refinement prevents new correction work; already-loaded models remain resident until exit.

Phone review dims whole words with a minimum constituent-token probability strictly below **0.90**. Punctuation-only tokens are ignored. These conditional decoding scores are an uncertainty hint, not calibrated correctness. GPU results carry their own word scores; manual edits remove highlighting. The textarea remains editable and accessible, with an inert decorative text mirror for per-word coloring. The glasses' native text API has container-wide brightness, so their review container is dimmed during a pending refinement when words are flagged; it returns to normal afterward.

The native accept box has no heading, edit hint or page counter. Longer questions keep up to three transcript lines per page with More/Send/Cancel controls. The box fits the visible transcript and stays within the existing eight-text-container limit. Partial updates with the same wrapped line count use native text updates; changing the line count rebuilds the geometry and clips any underlying figure to the new boundary.

**Compare with WAV file** runs a recording of up to 60 seconds through the CPU and GPU models and shows transcripts and timing. It never sends a question. Models loaded by the comparison also stay resident. Common WAV sample rates/stereo are resampled locally. Debug exports contain timing/backend/errors, not audio, transcripts or word scores; release builds omit diagnostics.

For an external service, choose **Speech provider · configured endpoint**, then set **Voice → Speech API base URL, model and API key** in connection settings. That mode sends a WAV to `/audio/transcriptions`; the legacy bridge keeps its own transcription route. Even Terminal itself does not transcribe audio. Recording starts only on an explicit hold or Speak, stops on release/cancel, and is capped at 60 seconds. Typed questions remain available.

Every destination origin must be allowed in the installed build. Even uses exact origins and standard CORS; it does not support a wildcard or a runtime arbitrary-origin permission. Build with the provider/Terminal and speech origins you intend to use:

```bash
PAGEBORNE_DEBUG_ASK_ORIGINS=https://your-desktop.example,https://your-inference.example,https://your-speech.example npm run pack:debug
```

The same origin list drives runtime checks and `app.json` permissions. Put private debug origins in the ignored `.env.debug.local` file to keep them out of source control. Debug includes diagnostic logging and exports; optional `PAGEBORNE_DEBUG_TERMINAL_STATE` embeds the local pairing token for automatic connection in this private package only. `npm run pack:release` (also `npm run pack`) creates the separate release package with logging disabled, ignoring private pairing state, debug origins and the legacy `PAGEBORNE_ASK_ORIGINS` test override. Both profiles allow the fixed public model-download origins independently of Ask. Release has no AI destinations by default; `PAGEBORNE_RELEASE_ASK_ORIGINS` explicitly configures approved release destinations. See the [build commands and outputs](README.md#build-and-verify).

Arbitrary addresses can be imported and used in the browser, subject to CORS. HTTPS is required for installed production connections. Local loopback HTTP is supported for testing. A public single build supporting arbitrary user-owned endpoints would need an approved networking mechanism or a separately designed fixed-origin relay. [Even networking](https://hub.evenrealities.com/docs/build/networking).

The SDK bundled with Pageborne supports long press/release and microphone input (`0.0.14`, Even App `2.2.9+`). [Input documentation](https://hub.evenrealities.com/docs/build/device-apis).

Releasing an empty or unrecognized silent recording quietly restores the previous reading/conversation view and unsent phone draft. It sends no question and creates no speech error. Microphone, model and connection failures still report their actual errors.

## Context and existing bridge installations

Text-only connections use a fixed **100,000 estimated token** source-context budget (400,000 characters), shared across documents. The former surrounding-text setting is removed and saved overrides are ignored. Actual token counts depend on the model and document; instructions, history and output also use tokens. Custom Terminal servers advertising document access receive the question and a location pointer only: file, reflow block/line, original PDF page and source coordinates when available. No quoted line, focus text or surrounding passage is included, including when restoring an older saved attachment. The first question (or a changed export) also identifies the available original/reflow/index files so the agent can navigate them itself.

In fallback mode, each new question captures a window centered on the current reading position. At the start or end it uses the remaining space on the other side; shorter documents fit in full. PDF context uses only the text prepared so far. Title, the page of the current reading position, and the current word/line accompany the text. The Ask panel shows the exact passage and estimated size. No other documents, original file bytes or figure pixels are sent. OCR errors can affect answers. The desktop agent maintains its own conversation history and may log prompts according to its configuration. Recent direct-provider conversations are saved on this device, separate for each paper and provider/model; up to four completed pairs are sent with a follow-up. Audio is not saved by Pageborne.

Existing 0.8.0 Pageborne AI-bridge connections remain supported and appear as **Existing Pageborne bridge**. The optional AI bridge supports server-configured Anthropic/OpenAI-compatible providers. Its legacy ChatGPT account adapter is experimental, disabled by default and not verified against a live account for this release. Explicit opt-in requires `PAGEBORNE_EXPERIMENTAL_CHATGPT=1`; it is not needed for desktop sessions or direct API connections. See [compatibility and optional integrations](COMPATIBILITY.md).
