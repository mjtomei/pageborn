# PDF reading and local preview

Version 0.5.0 adds local PDF imports. Markdown and text retain native text rendering. PDFs use cropped page images so fonts, equations, tables and figures keep their original appearance.

Version 0.5.1 fixes problems found in five real PDFs from the local reading library: narrow column gutters, connected vector diagrams, descenders at column transitions, binding shadows in scanned facing pages, and exact position restoration when neighboring crop bounds overlap. The [local review](test-results/reading-pdfs-final/REVIEW.md) includes before/after screenshots and the remaining readability limits.

Version 0.5.2 uses the full 576-pixel display width, tighter side crops, and full-width enlargement for paragraphs and figures. Rotated arXiv identifiers in the outside page margin are excluded from the reading crop. PDFs that draw body letters as outlines retain paragraph grouping, so short final lines stay at the same size as the rest of their paragraph. See the [width comparison and verification](test-results/pdf-width-20260921/REVIEW.md).

Version 0.5.3 removes detected side notes by default and adds **Keep margin notes** beneath **PDF layout**. This choice is saved separately for each PDF and also restores outside arXiv stamps. The Dartmouth v. Woodward scan is included in the [local margin review](test-results/pdf-margins-20260921/REVIEW.md).

Version 0.5.4 fixes issues found in an 18-page magazine and four technical papers (75 pages). Pale paper backgrounds, clipping paths and decorative text frames no longer prevent column detection. Reused vector symbols get bounds for each occurrence; multi-panel figures and ruled tables stay together. Two-column captions finish before the body text starts, and margin removal respects changes from a wide abstract to narrower body columns. See the [technical and magazine review](test-results/pdf-technical-verified-20260921/REVIEW.md) for examples, test scope and remaining limitations.

Version 0.5.5 adds **Normalize PDF colors**, enabled by default and saved per document. It identifies flat light, dark or tinted paper colors and strengthens foreground contrast, including colored text that would disappear in a simple luminance conversion. The page is normalized before column/crop analysis, and each cropped block gets a stable color profile so dark callouts on light pages can be handled separately. Original PDF bytes remain unchanged. See the [color normalization review and simulator screenshots](test-results/pdf-colors-review-20260921/REVIEW.md).

Version 0.6.0 fixes magnified scan debris, keeps fitting figures intact during paging, and adds **Reflow body text** with Small/Medium/Large sizes. Reflow uses embedded PDF text first and local English OCR for pages without usable text. See the [scan/reflow/figure review](test-results/pdf-reflow-20260923/REVIEW.md).

Version 0.6.1 improves the sharpness of non-reflowed PDF text and figure labels. The 900-pixel page image is now used only for layout analysis. Visible image sections render directly from the PDF at twice their display resolution, then reduce once to the output pixels. Flat-paper text receives a mild edge-sharpening pass; diagrams/photos keep their original tones. No new setting is needed. See the [before/after comparisons](test-results/pdf-sharp-20260923/REVIEW.md).

Version 0.6.2 fixes gaps in margin removal caused by short OCR words and slightly misplaced body-text boxes. Detected outside page numbers are removed along with side notes. When marginal content is kept, paragraph images split at clear line gaps where their outside width changes, so an annotation does not shrink the entire paragraph. Bottom footnotes and detected figures remain intact. See the [Dartmouth margin review](test-results/pdf-margins-20260924/REVIEW.md).

## Try it in a desktop browser

```sh
cd /path/to/pageborne
npm run pack:debug
npm run preview
```

Open <http://127.0.0.1:3461/> and use **Add files**. Select the imported PDF, then scroll the **Read from here** image preview. Clicking a point selects the glasses position; browsing without clicking leaves that position alone. The smaller **Glasses preview** shows the image and footer that will be sent. This is the same app interface used on the phone and does not need a glasses connection or the official simulator.

Files are stored locally in this browser's IndexedDB. It has its own library, separate from the installed Even app. The preview server serves static app assets only; documents are never uploaded. Keep using the same browser and URL to retain this preview library. `npm run preview` does not change the existing Prototype Mode URL or QR configuration.

## Reading behavior

Scan reflow compares fresh local OCR with an existing invisible PDF transcript where neighboring words and line positions agree. A conservative postprocessor corrects digit/letter confusions such as `1s` → `is` and low-confidence capitalization. It does not replace whole sentences, change punctuation, infer missing words or blindly spellcheck numbers and acronyms. Image-only scans still use the existing local OCR engine; no second model or remote service is loaded for consensus.

Underlines are treated as marks around the printed words. Recognized prose stays native text; low-confidence rows made from a verified long, thin underline are excluded. Written marks in the outside margins are saved as original image crops in **Written annotations**, separate from reading order and the figures gallery. Open a thumbnail on the phone to inspect it; previews do not move the glasses reading position. Uncertain regions, including handwriting overlapping printed text, may still remain images. Original PDF bytes are unchanged. Completed preparation caches include the annotation crops' locations; existing preparations rebuild once when the recognition version changes.

`npm run test:pdf-annotations` exercises OCR, the separate gallery, bounded previews, document changes and durable cache reload using an original synthetic scan. `PDF_BROWSER=webkit` selects WebKit; `PDF_SAMPLE=/path/to/scan.pdf` tests a local annotated scan without adding it to the repository.

PDFs become readable during preparation: the first usable page is followed by batches of three source pages. Provisional pages use the text and layout evidence available so far; a final pass compares the whole document to refine repeated headers, footnote sizes and section ordering. Updates restore the current source location, retain playback state and preserve the exact speed-reading word when its crop is unchanged. Browsing the phone preview remains independent of the glasses.

The final pass reuses provisional page layouts when the source text, masks, body/note sizes and section state match exactly. Changed evidence still triggers fresh analysis. No extra full-page canvases are retained. On devices supporting WebAssembly SIMD, OCR uses Tesseract's accelerated LSTM core; older devices keep the scalar core. Both engines and the same English recognition model are bundled for offline operation. Existing saved preparations remain valid. See [benchmarks and validation](PERFORMANCE-TESTING.md).

The phone and glasses show how many original PDF pages are ready. Position percentages, page counts, search and reading-time estimates cover the available portion until preparation finishes. At its end, playback stops without restarting the document; resume when more pages are ready. If the saved location is on a later page, ready pages remain visible while that location prepares, and the old save is protected. The app returns there when ready unless you start reading, navigate or open Ask in the available pages. Later-page bookmarks wait until their pages are ready. Footnotes remain accessible in their separate view as they become available. If later preparation fails, the ready portion remains readable and reopening retries preparation. Only completed layouts are written to durable preparation storage; closing during preparation does not yet save a resumable partial checkpoint.

PDF rendering yields between drawing continuations and analysis stages so the browser can process navigation. Switching documents cancels active PDF/OCR workers, and superseded previews release their canvases. `npm run test:loading-ask` exercises ready-page reading, Ask/return and twelve load/cancel cycles in Chrome with CPU throttling, and records the UI. `PDF_SAMPLE=/path/to/file.pdf` adds a real scan. By default replies are simulated; `LIVE_TERMINAL_STATE=/path/to/pairing.json` explicitly enables real Codex questions through that local Terminal, using synthetic passages in new test conversations. `SHOW_BROWSER=1` displays the test window on this workstation.

This is incremental preparation of an imported file, not network streaming. The local file picker/import still needs the complete file, and Pageborne does not fetch document URLs. PDF.js can support partial network loading via byte-range requests when the download source supports them; that would need a separate import source. See the [PDF.js loading FAQ](https://github.com/mozilla/pdf.js/wiki/Frequently-Asked-Questions#pdfjs-is-fetching-the-entire-pdf-file-from-a-server-can-it-fetch-only-the-required-portions).

Scanned pages with invisible OCR transcripts are recognized again from their pixels during reflow. Such transcripts can contain plausible English while omitting phrases and superscripts. Raised numeric suffixes receive a bounded, higher-resolution OCR pass; only references matching a recognized note on the same source page are bracketed. Repeated centered Roman headings in the transcript help recover section labels that scan OCR misses. A shallow strip of ink is reattached to the preceding text only when it connects across the crop boundary, preventing letter descenders from becoming separate images. There is no general semantic image classifier; uncertain graphics remain visible. Preparation format 7 rebuilds older saved preparations once, then reuses the result.

Open the **PDF** tab to access processing settings; **Hide** closes that panel. **Columns** chooses the page layout. **PDF text size** controls the reflowed passage preview. Native glasses text uses the fixed firmware font. The separate **Phone text** control appears only for Markdown/plain text.

The default **Automatic columns** layout analyzes each page separately. Full-width headings, paragraphs and figures separate bands of columns. Within a two-column band it reads the left column from top to bottom, then the right column. This supports pages and documents that alternate one- and two-column sections. **Single column** disables column splitting; **Two columns** prefers a column split while retaining detected spanning content. The choice is saved per document.

**Keep margin notes** is off by default. The app identifies narrow outside notes beside repeated body lines, then removes those margins and detected outside page numbers from the preview, glasses images and search. Detected figure labels stay in the reading content. Recognized bottom footnotes move to the separate Footnotes view when reflow is enabled. Turn the option on to include the side notes, outside page numbers and stamps. Image paragraphs split at clear line gaps where outside content changes their width: annotated lines fit with their notes, and surrounding body lines expand to the display width. Short paragraph endings keep the surrounding body scale; detected figures are not split this way. Changing the option rebuilds the PDF layout while retaining your place where possible; the original PDF bytes are never changed. Detection is conservative: ambiguous notes, inaccurate OCR and textless scans can leave marginal content in place.

**Normalize PDF colors** shows dark ink on clean white paper in **Read from here**. For the glasses, this is inverted to bright foreground pixels and zero-intensity background pixels. The G2 displays bright pixels as green and zero pixels as unlit/transparent; the phone's **Glasses preview** tints the grayscale frame green. See [Even's display documentation](https://hub.evenrealities.com/docs/build/display). A white page therefore does not become a glowing green rectangle. Turn normalization off for an original-color phone preview and the earlier grayscale/inversion behavior on the glasses. Changing this option rebuilds the layout while preserving the source position where possible.

Normalization retains antialiased edges and uses one color profile for a whole block, rather than adjusting brightness for each viewport. Regions without a reliably flat background, such as photographs or gradients, retain ordinary grayscale detail. This is a heuristic, not semantic text/background segmentation: complex artwork, text over photos and effectively invisible text cannot be guaranteed to separate correctly. Color-only distinctions in diagrams are also lost on a monochrome display.

White side margins are cropped per paragraph or figure, retaining one source pixel at either side to protect letter edges. Thin scan debris and sparse marks are filtered. Ordinary image paragraphs enlarge to fill 576 pixels with a 4× cap; short isolated fragments and page numbers have a 2× cap, preventing extreme enlargement of small scan artifacts. This is conservative: handwriting and uncertain marks may remain.

Short image runs, including figures and displayed equations, are centered vertically within the glasses' reading area, above the footer. Horizontal margins are balanced too. The glasses mirror uses the same image. During autoscroll, a short image remains intact while its allocated reading interval elapses; taller images keep their scroll position. The continuous phone passage keeps source spacing. This display-only change reuses existing preparations and preserves bookmarks.

**Fit figures to one screen** is on by default and saved per PDF. Moderately tall figures are scaled down to fit the 258-pixel reading area when their resulting width is at least half the display. Taller figures stay scrollable at full width. Turn this off to preserve detail in dense diagrams and tables. Any figure that fits is deferred intact to the next screen when it would otherwise start partly at the bottom of a page. The continuous phone preview and autoscroll show the entire strip without these paging gaps. Page turns prefer paragraph starts and use overlapping steps within long blocks. The final short block can start at the top with blank space below it.

**Reflow body text** is on by default and saved per PDF. It wraps identified prose at 20, 24 or 28 pixels, with a small side inset and paragraph spacing. Embedded text is used when available; pages with fewer than 20 usable text characters, invalid geometry, corrupted encoding, or severely fragmented English text run local English OCR. Figures, ruled tables, likely unruled tables and displayed equations remain images. Low-confidence OCR and blocks whose visible ink is not explained by recognized text also keep their scan. Reflowed prose uses native glasses text; figures and uncertain regions switch to image display. Image refresh latency is unchanged. Inline formatting is simplified, and complex math, damaged text layers or unusual layouts can be misclassified. Disable reflow to inspect the original content.

**Footnotes** in the glasses menu pauses reading and opens nearby recognized footnotes. A high-confidence scanned continuation below a separating rule can inherit the preceding page’s footnote number, even when no number is printed again. It is labeled “continued” and excluded from the main passage. Without a recent numbered footnote, the unnumbered text stays in the body. Recognized footnotes are excluded from the main reflowed passage, body search and timed word groups. Notes retain their original number and PDF-page label; swipes page through them. A tap, Back or the same menu option returns to the unchanged page/word group, still paused. **PDF → Footnotes** on the phone opens the same view. Captions still appear after their titled section. Unknown notes may remain in the body because detection is conservative. The original file and saved preparation retain all notes; body/notes views are derived from the completed preparation without repeating OCR.

Recognized raised references use brackets, such as **[12]**, in the phone passage, native glasses text and speed-reading words. The corresponding note is labeled **Footnote [12] — PDF page …**, and its opening marker uses the same brackets. References must match a recognized note on that source page; ambiguous digits, ordinary counts and uncertain OCR stay unchanged. Added brackets are included in line-width calculations. Original scan images are unchanged, and existing prepared PDFs receive the formatting when reopened.

Scan recognition reports page/progress status and runs one worker at a time. Recognized text for the last 64 pages is cached in memory for setting changes. Complete preparations are also saved in durable app storage and restored on reopening. Changes to PDF formatting or preparation format rebuild the result once; source files and bookmarks remain intact. Scanned documents can take considerably longer to open. Switching documents terminates recognition, including during engine startup; a failure falls back to scan images with a visible notice. OCR is English-only and can misread words, numbers and punctuation, especially in old scans.

Autoscroll moves by native rows in prose and 27-pixel steps in images. Its speed control is labeled **steps/min** for PDFs, and it waits for a complete glasses frame before advancing. Image regions use four tiles plus the existing native footer; prose stays native. G2 image updates may appear tile by tile. After an image, native text starts with three lines by default, configurable under the shared reading settings. Switching to a Markdown document or the glasses document picker rebuilds the native text surface.

Contents lists original PDF pages. Search uses embedded text and, when reflow is enabled, recognized scan text. Bookmarks retain source coordinates and text offsets to preserve the passage across font-size changes, image/reflow switching and reopening. OCR text is separate from the original PDF; the stored file is never modified.

## Limits and implementation

PDFs may be up to 16 MiB and 1,000 pages; the total library limit is 64 MiB. Password-protected PDFs need their password removed first. Blank/unrenderable documents show an error. Geometry cannot establish author-intended order for every PDF: unusual sidebars, three or more columns, dense diagrams, overlapping objects and scans can confuse automatic layout. Inspect the browser preview and use the layout override when needed.

A short, left-aligned heading between two separate sets of columns can look like a heading inside the left column. This remains visible on page 18 of the Coherence magazine: its final references subsection begins before the preceding right-column references finish. Publisher headers/footers and scan artifacts can also interrupt reading. Keeping a dense table or figure intact does not guarantee that its smallest labels will be legible at 576 pixels; there is no horizontal zoom/pan yet.

Rendering uses [Mozilla PDF.js](https://mozilla.github.io/pdf.js/) 6.3.289 (legacy browser build). The worker, fonts, CMaps and image-decoder WASM are bundled so a newly imported PDF can render offline. `BinaryDataFactory` supplies local bytes; no CDN or remote conversion service is used. PDF JavaScript/XFA execution is disabled. PDF.js and bundled resource licenses are included in the package. The larger app bundle is intentional for offline PDF support. [Tesseract.js](https://github.com/naptha/tesseract.js) 7.0.0, its portable LSTM WASM core and English language data are bundled as local worker/Blob resources; OCR makes no network requests. Their licenses are included. A small transport owns the pinned worker protocol so initialization failures, timeouts and cancellation reject pending jobs reliably.

The layout combines raster whitespace analysis with PDF text bounds and image/vector drawing bounds. Visible path bounds follow their current transforms; clipping paths and pale fills do not count as figures. Connected paths and nearby panels with evidence of a shared figure are grouped before cropping. Repeated horizontal rules protect tables from false column splits. In textless landscape scans, narrow, nearly page-height binding shadows are excluded from layout and cropping. Tiny isolated scan specks are ignored. Margin detection joins fragmented text lines, estimates repeated body edges, and reserves wider text/figure bands before masking an outside lane. Comparable text columns running the length of the body are retained. The same masks apply during layout and rendering, including after page-cache eviction. Large source scans are downsampled by PDF.js to a 32 MB image-canvas budget rather than being discarded above 16 megapixels. Decoded page images are released when their analysis page is evicted or the tile renderer moves to another page. Two analysis page canvases are retained at a time; each is bounded to two million pixels and 4,096 pixels high. Display sections use a separate cache of at most twelve 576×384-pixel tiles. One tile renders at a time, with a temporary canvas below one million pixels at 2× resolution. A small halo keeps antialiasing/sharpening consistent at tile boundaries. Closing the document cancels the active render and queued requests. Layout, crop geometry and bookmarks are independent of display quality. The scrollable preview mounts only nearby image tiles. Selection changes discard old PDF work, and SDK image transfers use the existing serial lane. Original PDF bytes are stored in the same persistent phone library, encoded and chunked; layout images are rebuilt from them.

## Scan decoder compatibility

JPEG 2000 and JBIG2/CCITT decoders are bundled with the reader, including their JavaScript fallbacks. Older WebKit versions lack the relaxed SIMD instructions used by PDF.js's OpenJPEG WebAssembly decoder. The fallback keeps those scans visible on the glasses and in the web reader, including offline. Decoder modules remain available during page-cache cleanup and are released when the document closes.

`npm run test:pdf-decoders` checks original JPEG 2000 test imagery in both readers, offline rendering, forced WebAssembly failure, and decoder cleanup. Set `PDF_DECODER_BROWSERS=chromium,webkit` and optionally `WEBKIT_PATH` to include WebKit. No library documents are included in the fixtures.
